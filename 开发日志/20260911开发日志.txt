  ──────
  ### 🔍 1. SSH 连接建立失败（Dial / Handshake Timeout）

  如果 GitHub Actions 在连接一开始就报错（如 ssh: handshake failed 或 dial tcp xxx:22: i/o timeout）：

  • 原因 A：GitHub Secrets 未配置或拼写错误
      • 请检查仓库的 Settings -> Secrets and variables -> Actions。
      • 确认是否存在 SERVER_HOST（服务器 IP）、SERVER_USER（如 root 或 ubuntu）、SERVER_SSH_KEY（私钥内容）。
  • 原因 B：私钥格式不对
      • SERVER_SSH_KEY 必须包含完整头尾（例如以 -----BEGIN OPENSSH PRIVATE KEY----- 或 -----BEGIN RSA PRIVATE KEY-----
      开头，且结尾带换行）。
  • 原因 C：云服务器安全组/防火墙封禁
      • 阿里云/腾讯云/AWS 安全组没有放行 GitHub 的 SSH 端口（默认 22 端口）。

  ──────
  ### 🔍 2. 80 端口冲突 (port is already allocated)

  如果报错信息包含 Bind for 0.0.0.0:80 failed: port is already allocated：

  • 原因：服务器上原生 Nginx 或其他服务占用了 80 端口，导致 docker run -p 80:80 启动失败。
  • 解决方法：
  在服务器上关闭占用 80 端口的原生 Nginx（sudo systemctl stop nginx），或修改 deploy.yml:46 中的映射端口（例如改为 -p
  8080:80）。
  ──────
  ### 🔍 3. sudo 需要密码验证 (Sudo password required)

  如果报错包含 sudo: a terminal is required 或 a password is required：

  • 原因：脚本中使用了 sudo docker ...，但服务器上当前 SSH 登录的用户没有配置 sudo免密执行。
  • 解决方法：
      • 方案一：将当前用户加入 docker 用户组（省去 sudo）：
      在服务器上运行：sudo usermod -aG docker $USER 并重启 docker 服务。
      • 方案二：在 /etc/sudoers 中设置免密。

  ──────
  ### 🔍 4. git clone 或 git reset 失败

  如果报错包含 fatal: destination path '/var/www/dreamclip-website' already exists 或 Permission denied：

  • 原因：/var/www/dreamclip-website 目录存在但权限属于 root，普通用户没有写入权限。

  ### 🎯 错误根因分析

  日志中的报错提示：
  dial tcp 104.21.53.75:22: i/o timeout

  这里的 IP 104.21.53.75 是 Cloudflare 的 CDN / 节点 IP。

  • 为什么会 timeout：
  在 GitHub Secrets 里，你的 SERVER_HOST 填写的可能是你的域名（或者被 Cloudflare 代理的 IP）。
  Cloudflare 默认只代理 HTTP/HTTPS 网页流量（80/443 端口），不支持 SSH 协议（22 端口）。当 GitHub Actions 尝试通过
  SSH 连接 Cloudflare 的节点 IP 时，连接会被静默丢弃，从而报 i/o timeout 错误。
  ──────
  ### 💡 解决方案

  只需要修改 GitHub 仓库的 Secrets 即可，不需要改代码：
  1. 打开 GitHub 仓库：Settings -> Secrets and variables -> Actions
  2. 找到 SERVER_HOST 这个 Secret，点击编辑（Edit）。

  3. 将它的值从现在的域名（或 Cloudflare IP）修改为你云服务器的真实公网 IP（例如阿里云/腾讯云控制台上显示的 xxx.xxx.
  xxx.xxx 真实 IP 地址）。
  4. 保存后，在 GitHub Actions 中点击 Re-run all jobs 重新运行构建。
  ──────
  ### 🛡️ 顺带检查云服务器安全组

  确保云服务器（阿里云 / 腾讯云 / AWS 等）控制台的安全组规则中，22 端口（或你的自定义 SSH
  端口）入站规则已放行/允许访问。

  • 完全可以使用：域名（例如 https://api.yourdomain.com 或 https://yourdomain.com/api），而且强烈推荐开启 Cloudflare
  代理（橙色小云朵 🟠）！
  • 原因：
      1. 完全兼容：API 请求属于标准的 Web HTTP/HTTPS 流量，Cloudflare 会完美代理转发。
      2. 免费 HTTPS/SSL 证书：无需自己配置复杂证书，Cloudflare 自动提供高强度加密。
      3. 防 DDoS 攻击与隐藏源站：开启代理后，外界只能看到 Cloudflare 的节点，无法直接攻击你的真实服务器 IP。
      4. CDN 加速与防刷：能帮你的 API 和静态资源进行缓存加速。

  ──────
  ### 💡 总结最佳实践

  • 开发 / 部署（给 GitHub Actions / 运维用）：
      • GitHub Secrets 里的 SERVER_HOST 填 真实服务器 IP。
  • 线上 / 业务（给前端网页 / 玩家 / API 用）：
      • 前端 fetch('https://api.yourdomain.com/...') 统统填 域名，并放心开启 Cloudflare 代理！
