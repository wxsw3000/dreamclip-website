  ### 二、 核心关键点深度评判

  #### 1. 为什么说“情绪胶囊图文”是 AdSense 审核的破局点？

  • AdSense 拒审最常见的死因：纯游戏导航站、纯功能型工具站常被判定为 “低价值内容 (Low-value content)” 或 “内容匮乏
  (Scraped/Thin content)”。
  • 您的破局设计：规划了 8-10 篇 800~1500 字的原创角色小品与情绪胶囊，图文并茂，具有实质性文本深度。这正是 Google
  爬虫最喜爱的原创深度内容，过审概率将大幅提升。

  #### 2. 域名、服务器与 SEO 访问体验

  • 免备案策略（.cn + 硅谷服务器）：
      • .cn 域名只需完成注册商的实名认证即可解析到海外服务器，免去繁琐的 ICP 备案流程，能够快速上线。
      • 注意事项：由于目标用户包含国内访问，建议接入 Cloudflare（开启免费 CDN 与
      SSL），既能加速国内外静态资源分发，又自带免费 HTTPS 证书，还能抵御恶意攻击。
  • SEO 抓取友好性：
      • 文章和角色详情页要确保 Google 爬虫能直接抓取到 HTML 文本（采用服务端渲染 SSR 或预渲染静态 HTML），避免纯客户端 JS
      异步加载导致爬虫抓到空白骨架屏。


  #### 3. Google AdSense 账号与变现策略

  • 国内个人 AdSense 账号的关键细节：
      • 真实地址：收入满 10 美元时，Google 会从海外寄出一封包含 6 位 PIN
      码的平邮纸质信件，地址务必精确到门牌号，并预留电话。
      • 收款方式：中国区 AdSense 统一走国内银行电汇（如招行、工行等电汇结汇），流程成熟合规。
  • 广告接入节奏：
      • 先以主站图文内容通过 AdSense 网站级审核；
      • 待站点有稳定自然流量后，再申请 AdSense for Games (H5 游戏插屏/激励广告) 权限，该节奏顺序完全正确。

  隧道连接时非常典型，通常是以下 两个原因之一 引起的：
  ──────
  ### 🔍 原因 1：【常规】标签页中的主机地址填错了（最常见，90% 的概率）

  使用 SSH 隧道时，Navicat 的两个标签页分工不同：

  • 【SSH】标签页：填您的服务器公网 IP 或 dreamclip.cn；

  │ 为什么？
  │ 因为 SSH 通道已经成功登录进了服务器内部，在服务器内部找 MySQL 时，它的地址就是它本地的 127.0.0.1。如果填了公网
  │ IP，数据包会尝试绕回公网被服务器防火墙直接拦截丢弃。

  👉 请检查并修改：
  在 Navicat 的 【常规】 标签页中，将 主机 (Host) 修改为纯数字的 127.0.0.1。
  ──────

  MySQL 8.0 默认在客户端握手时会尝试做 DNS 反向解析，如果解析不到主机名就会触发通信包握手超时（2013 错误）。

  1 分钟解决方法：
  在您的云服务器终端中执行以下两行命令，关闭 DNS 反向解析并重启 MySQL：

    sudo bash -c 'echo -e "\n[mysqld]\nskip-name-resolve\n" >> /etc/mysql/mysql.conf.d/mysqld.cnf'

    # 2. 重启 MySQL 服务
    sudo systemctl restart mysql

  ### 🔍 深入解析三大核心考量

  #### 1. 为什么服务间通信走 127.0.0.1？（性能极致）

  • 同机部署：当前在阿里云 ECS 上，底座（8000）、业务微服务（8081）和网关（80）运行在同一台主机中（使用 --net=host
  主机网络栈）。
  • 心跳探活与内部转发：
      • 底座 mcp-base 每 20 秒 就要对微服务发起一次健康检查请求；
      • 网关 mcp-portal 收到用户的阅读/剧情请求后，需要将请求转给业务服务；
  • 走内部环回地址 127.0.0.1，网络延迟仅 0.1 毫秒、零公网带宽消耗、吞吐量极高。
  ──────
  #### 2. 为什么绝对不能直接配公网 IP / 端口？（安全最佳实践）

  • 安全组防御：阿里云安全组策略只开放了 80（HTTP）和 443（HTTPS），端口 8000、8081 等底层端口全部处于防火墙内部保护中。
  • 防止被直接攻击/绕过鉴权：
      • 如果将 8081 直接暴露给公网，任何人都可以直接调用底层无防护的 API 绕过网关鉴权或抓取原始数据；
      • 通过网关统一暴露（https://dreamclip.cn/api/universe/**），所有请求都必须经过统一网关的安全过滤、限流与统一 CORS
      策略。

  ──────
  #### 3. 未来如果是「多台服务器 / 集群化」分布式部署时怎么配？

  这正是 MagicStar MCP 模块化配置平台支持动态注册与编辑 Base URL 的核心价值：

  • 单机模式（当前阶段）：微服务都在同一台 ECS 实例，Base URL 填 http://127.0.0.1:8081；
  • 分布式集群（未来扩容）：若未来业务量大增，将角色宇宙服务单独部署到专用的高性能机器 Node-B（例如阿里云内网 VPC IP 172.
  16.0.5）：
      • 微服务只需将注册地址改为 http://172.16.0.5:8081（阿里云内网高速专线，依然不暴露公网）；
      • 底座和网关即可自动通过内网 VPC 进行跨机集群治理与负载转发。

  ### 二、 核心实操建议（四步到位）

  #### 1. Cloudflare 开启「泛域名解析（Wildcard DNS）」与免费 SSL

  这是最爽快、一劳永逸的配置，今后增加任何新微服务都无需再手动添加 DNS：

  • 操作方式：
      • 在 Cloudflare DNS 面板添加一条记录：
          • 类型：A 或 CNAME
          • 名称（Name）：*（通配符）
          • 目标（Target / IPv4）：47.251.71.143
          • 代理状态：已代理（开启橙色小云朵）

  • 效果：
      • Cloudflare 的 Universal SSL 证书默认包含 *.dreamclip.cn；
      • 无论是 base.dreamclip.cn、universe.dreamclip.cn 还是未来的 ai.dreamclip.cn，无需申请证书，全自动拥有全球 CDN
      加速与 HTTPS 保护。

  ──────

  #### 3. 跨子域名统一单点登录（SSO across Subdomains）

  • 效果：整个 *.dreamclip.cn 域名树下的所有微服务共享同一个登录会话，实现无缝单点登录。
  ──────
